# 迁移、部署与回滚约束

当前为设计，不是可直接在现有服务器执行的迁移命令。T11 / T13 / T14 实现并演练后才执行。

## 演练输入与数据处理

1. 在受控环境复制旧平台库、ERP 各账套和附件；副本和凭据不进入公共仓库。
2. 提取 User、Membership、Tenant 的结构及数量。验证旧 scrypt 哈希在新认证模块中可用，禁止生成明文密码迁移表。
3. 保留 User.id；平台 Company.id 复用旧 Tenant.id；财务 LedgerBinding.id 保留旧 Tenant.id，新增 platformCompanyId。
4. 将 Membership 转换为明确的应用角色和公司范围；原财务 admin 可映射提交权限，reviewer 只按已有实际能力映射。平台管理员身份另行授予。
5. 历史 Audit.userId 保持稳定，财务库无跨库用户外键。旧账号与 Membership 表先只读保留用于核对，兼容窗口结束后才清理。
6. 迁移程序必须支持 dry-run、幂等重试、数量对比、孤儿引用检测与脱敏报告。

## 正式切换

- 备份平台库、财务业务库、ERP 各账套、附件和所需加密密钥，校验文件完整性，并确认存在可用的恢复演练记录。
- 在预先约定的短维护窗口禁止财务写入，等待处理中的提交明确完成或失败，排空或暂停后台写任务。
- 执行最终增量迁移与映射核对。旧会话全部失效，入口切换后使用平台账号重新登录。
- 同一业务只能有一个可写入口；旧镜像保留，不保留另一个可写实例。
- 核对单据数量和状态、项目预算、银行匹配、历史审计、凭证引用，以及各账套总账借贷合计。

## 回滚

优先采用兼容数据库结构的应用镜像与路由回滚。新增字段和旧字段至少保留一个已验证的兼容窗口；删除字段与破坏性迁移不与第一次切换绑定。

如果切换后已经产生新凭证或财务记录，不允许直接恢复旧快照覆盖新账。先停止写入，确定新记录及 ERP 状态，按演练过的前向修复或增量回迁方案处理。恢复备份只适用于明确的数据恢复场景，并核对恢复点之后的数据。

## 验收证据

证据包含版本、时间、脱敏数量、断言结果和恢复验证，不包含连接串、账号密码、原始财务附件或数据库转储。实际服务验收未执行时必须记录未执行，不能用模拟输出替代。
