# 正式切换准备

本期交付独立测试环境。正式系统目前仍由原入口承接写入，测试环境的虚构验收凭证不能回写正式账套。

## 切换前

1. 确定正式域名、TLS、生产入口和维护窗口；盘点原系统中所有直接写 ERP 的入口与后台任务。
2. 准备全新的生产平台库、财务库和上传卷。不要把当前演练数据库当作生产库，因为其中保留了测试凭证。
3. 核对生产公司的账套映射、人员角色、独立提交权限和异常账号。平台管理身份与财务身份分别确认。
4. 对切换版本做备份恢复演练，并保留对应镜像、迁移脚本、依赖锁定文件及私有密钥。
5. 当前迁移工具面向固定的演练副本，遇到历史冲突会拒绝覆盖。正式全量或增量迁移规则、生产映射和写入冻结步骤需要针对最终快照单独演练，不能直接对生产库运行当前演练命令。

## 维护窗口

停止原财务写入口和后台写任务，等待处理中单据明确完成或失败，禁止其他入口继续向同一账套写入。重新备份所有数据库、ERP 站点、附件和密钥，再迁移最终数据。

核对用户、公司、成员授权、单据状态、项目、银行匹配、审计、凭证引用和总账借贷合计。清理旧登录会话。先做受控只读核对，通过后只开放一个正式可写入口。

## 出现异常

- 新增财务记录之前，可按事先验证的维护窗口方案切回原入口。
- 已有新增单据或凭证时，优先退回兼容应用镜像并保留数据库与文件卷；禁止恢复旧快照覆盖新账。
- 涉及数据修复时，先停止写入，逐条核对平台与 ERP 状态，再前向修复或按已演练方案增量回迁。

本次已经验证应用回滚保留新凭证。跨 schema 回退和生产增量回迁没有自动执行，不能据此承诺任意版本都可无损回滚。
