# SPEC-001：统一平台与财务子系统

版本：0.1.0；状态：待评审。机器可读要求、验收 ID 与任务关系见 `spec.json` 和 `tasks.json`。

## 用户路径

用户进入统一门户，完成一次登录，选择有权限的公司；平台展示可进入的应用与菜单。进入财务后直接看到业务页面，保留单据、项目、流水、凭证和报表能力。切换公司或子应用后，页面与接口使用新的上下文。退出后，各子系统不能继续提交操作。

平台管理员配置账号、公司、应用和授权；财务入账操作需要独立授权，不能因为是平台管理员就自动拥有入账权。

## 范围与行为

### 登录与授权

- 账号与密码哈希只存在平台库。统一会话使用 HttpOnly Cookie；正式环境 HTTPS / Secure / SameSite，写接口校验 Origin 并提供 CSRF 防护。
- 财务 API 调用平台内部鉴权接口，明确请求应用、公司和操作；不能信任浏览器提供的身份或角色。
- 停用账号、退出会话或撤销权限后，正式入账等敏感写操作立即拒绝；普通读请求授权缓存最多 30 秒。
- 平台认证服务不可用时拒绝新的敏感写入；错误不把令牌、密码或 ERP 凭据写进响应和日志。

### 微前端

- `/finance/*` 激活财务子应用，主应用只提供一套导航和 Layout。
- 财务实现 bootstrap、mount、unmount，使用传入的容器创建 React 根节点。
- 子路由支持直接打开、刷新和前进后退；主应用不吞掉 API 或静态资源路径。
- 公司切换取消旧请求，过期响应不得覆盖新公司界面；未保存编辑提示由子应用返回，取消切换时保留原上下文。
- 卸载清理 React 根、订阅、监听、定时器和请求；弹窗限定挂载容器，避免全局 CSS 污染。
- 子应用是可信的同源代码，乾坤沙箱不作为安全隔离边界；应用资源只能来自部署配置的受信路径。

### 数据与财务

- 平台拥有公司基础档案，财务拥有 ERP 账套映射、会计锁期及财务设置。
- 公司列表来自平台授权；财务是否已开账由财务接口提供，未开账状态明确显示。
- 平台数据、财务业务数据、ERP 正式账务分别存储，通过 API 与稳定 ID 关联，不跨库建外键。
- 旧用户 ID、旧账套 ID、单据和历史审计保持可追溯；密码哈希可验证兼容，旧会话在切换时统一失效。
- 财务原有“审核创建草稿 → 明确确认正式提交”、借贷平衡、锁期、公司校验和幂等继续由财务 API 与 ERP 执行。

## 不在本期的内容

新增采购库存业务、集团合并报表、新的税务合规承诺、跨组织 SaaS 租户体系、对外身份供应商和复杂审批引擎。可在后续新 Spec 中单独定义。

## 验收方式

每个 AC 都绑定任务与验证类型。HTTP 用例可由本仓库验收脚本对真实服务执行；浏览器、数据库和恢复验收在相应任务中产出实际测试及证据。计划中的验收默认未执行，不因规格检查成功自动变成通过。

固定的虚构用户角色：录单员、审核员、财务提交员、仅平台管理员；公司使用 `sample-a`、`sample-b`，不包含真实企业或服务器资料。
